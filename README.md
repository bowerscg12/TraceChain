## Spike question (fixed before testing)

> Can PostgreSQL and the TraceChain API store item details, read them back, and produce a hash that matches the
> one on the blockchain every time — and can the comparison catch a record that really was changed?

### Requirements and risk under test

| ID | Requirement | Where it is tested |
|---|---|---|
| FR-01 | Register a pair with a unique ID; duplicates rejected | Test 3 409 group; contract duplicate-register check |
| FR-02 | Origin record stored exactly as entered; missing fields rejected | Test 1 stored-as-entered check; Test 3 400 group |
| FR-06 | Public provenance lookup with no account | `GET /items/:itemId` and the page need no credentials (Tests 1–2) |
| FR-07 | No editing of confirmed entries | DELETE on confirmed → 409; contract has no update/delete |
| FR-08 | "Verified" only when the record checks out | Test 1 (all Verified), Test 2 (all tampered Not verified) |
| NFR-04 / NFR-05 | No personal data on-chain; only itemId + hash | `register(bytes32 itemId, bytes32 detailsHash)` is the only write |
| NFR-09 | "Verified" is not a claim the physical item is genuine | Plain-text statement on the verification page |
| D6 Risk 7 | API/browser serialization drift makes a genuine pair look fraudulent | One spec, two independent implementations, hash equality across API, Node, Chromium and chain in 3 timezones |

### Pass marks (set before running)

| Test | Pass mark |
|---|---|
| Test 1 — Consistency | 100 of 100 records: POST hash = Node recompute from GET = browser hash = on-chain hash = Node recompute after API restart, and page shows "Verified". Must pass with API `TZ` and browser `timezoneId` set to UTC, America/New_York and Asia/Tokyo. |
| Test 2 — Tamper detection | 200 of 200 direct-SQL edits (20 records × 9 hashed fields + 20 swaps) show "Not verified", and 0 false alarms across all 100 restored records. Whitespace-only edits are recorded, not judged. |
| Test 3 — Validation | 400 group 10 of 10; 409 group 10 of 10. Other API/contract/page behaviours recorded outside the counted groups. |
| Informational | Request durations and page verify times (min / median / p95). Not judged. |

## What this spike substitutes, and how that limits the result

| Real design | Spike stand-in | Limitation |
|---|---|---|
| Ethereum Layer 2 network | Local Hardhat node (`chainId` 31337) | Both are EVM chains, so `bytes32` storage and reads behave identically. Fees, confirmation latency and L2 finality are **not** tested here (Nick Crockett's spike). |
| Nick Crockett's TraceChain contract | `contracts/TraceChainStub.sol`, clearly labelled stub | Minimal: admin + `isAuthorized`, `register`, `getItem`, no update/delete. The real contract's ownership transfer and events are out of scope. |
| Wallet signature authentication of producers | `X-Producer-Address` header checked against an allowlist in `.env` | Anyone who knows an allowlisted address can call the API in this spike. The API still sets `registeredBy` from the header, never from the body. Real signature checking (e.g. EIP-191 / SIWE) is future work. |
| Nick Frank's consumer frontend + QR scan | `public/verify.html` served by the API | Same-origin static page; QR scanning and multi-device behaviour are **not** tested (Nick Frank's spike). The hashing file `public/verify-hash.js` is the reusable part. |
| Windows 11 laptop with winget installs | Linux container with Git, Node 22 LTS, gh, native PostgreSQL 16 and Playwright Chromium already present | Tool versions are recorded in `results/environment.txt`. All scripts are plain Node and run unchanged on Windows. |
| Native `solc` download by Hardhat | npm `solc@0.8.28` (solc-js) wired into Hardhat's compile task | The container cannot reach `binaries.soliditylang.org`. Same compiler version, JavaScript build. |

Stub contract compiles with no optimizer; this does not affect what is stored or read.

## Setup

Prerequisites: Git, Node.js 20+ (22 LTS used), PostgreSQL 16 running locally (native install, not Docker), GitHub CLI
optional. On Windows: `winget install Git.Git OpenJS.NodeJS.LTS PostgreSQL.PostgreSQL.16 GitHub.cli`.

```bash
git clone <repo> TraceChain && cd TraceChain
npm ci                       # installs the exact pinned versions from package-lock.json
npx playwright install chromium   # only if Chromium is not already installed for Playwright 1.63
cp .env.example .env         # then edit: PGPASSWORD, PG_SUPERUSER_PASSWORD
```

Create the database role once (as the PostgreSQL superuser), matching `.env`:

```sql
CREATE ROLE tracechain LOGIN PASSWORD '<PGPASSWORD from .env>';
CREATE DATABASE tracechain OWNER tracechain;
```

`.env` is gitignored. Only Hardhat's default, publicly known local test accounts are used; never real keys.

## One-command run

```bash
npm run spike
```

This resets the database, starts a Hardhat node, compiles/deploys the stub contract, starts the API as a child process
with the given `TZ`, registers all 100 records through the full flow (POST → `register()` transaction → PATCH confirm),
runs Tests 1–3 in headless Chromium, prints the PASS/FAIL table, writes `results/<timestamp>/` and updates the results
section above. Exit code is non-zero if any pass mark fails.

Useful variants:

```bash
SPIKE_TIMEZONES=UTC SPIKE_TESTS=1 npm run spike   # quick: Test 1 only, one timezone
npm run hash:selftest                             # spec test vector + normalization rules
npm run db:reset                                  # drop, recreate, migrate
npm run data:generate                             # regenerate data/items.json (same seed -> same file)
```

`npm run spike` compiles the stub contract automatically if the artifact is missing (`npm run chain:compile` does it by hand).

## API summary (D4 Interfaces 1, 2 and 4)

| Method | Path | Auth | Behaviour |
|---|---|---|---|
| POST | `/items` | `X-Producer-Address` on allowlist | Validates 8 body fields, generates `TC-YYYY-NNNNNN`, normalizes, hashes, stores `pending`. 201 `{ itemId, itemIdBytes32, detailsHash }`. 400 names the bad field. 401 missing/unknown producer. 409 `This item ID is already registered.` |
| GET | `/items/:itemId` | none (public) | Stored values + `status`. Never returns or recomputes a hash. 404 if unknown. |
| PATCH | `/items/:itemId/confirm` | producer | `pending` → `confirmed` after the on-chain transaction confirms. |
| DELETE | `/items/:itemId` | producer | Removes a `pending` record after a failed transaction. 409 for confirmed records (FR-07). |
| GET | `/item/:itemId` | none | The verification page. |
| GET | `/config` | none | RPC URL, stub contract address and ABI for the page. |

## Known limits of this spike

- No wallet signature verification; the allowlist is a stand-in.
- The "API stopped" page check is done by opening the page, stopping the API process, and clicking "Check again"
  (the page itself is served by the API in this spike; in the real design Nick Frank's frontend is hosted separately).
- Stopping the Hardhat node discards chain state, so the "RPC stopped" check runs last.
- Performance numbers are recorded only as context; they are not what this spike measures.
